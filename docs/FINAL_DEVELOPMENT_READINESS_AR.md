# وثيقة التطوير النهائي وتجهيز OmniWave للنشر

## الغرض ونطاق القرار

تحول هذه الوثيقة متطلبات التحديث الشامل إلى قرارات متوافقة مع **Expo وReact Native**، لا مع أطر Flutter مثل Bloc. يعتمد OmniWave أصلًا على مزودات React محلية قوية (`ThemeProvider` و`PlayerProvider` و`VideoProvider`) مع عقود TypeScript وتحقق محلي. لذلك لا يستبدل هذا التحديث معمارية عاملة بمكتبة حالة إضافية بلا حاجة؛ بل يقوي الاسترداد والتنقل والحدود الأمنية وقابلية اختبار النشر.

> **قاعدة الإصدار:** النجاح في معاينة الويب والاختبارات الآلية لا يثبت الصوت في الخلفية أو شاشة القفل أو Bluetooth أو المشاركة أو الأذونات أو PiP أو التدوير. تظل هذه خصائص بناء أصلي وتتطلب أدلة iOS وAndroid فعلية قبل ادعاء اعتمادها. [1] [2]

## 1. الإعدادات والسمات واللغات

| المتطلب | التطبيق في OmniWave | الحالة |
|---|---|---|
| إدارة حالة مركزية وتحديث فوري | `ThemeProvider` يملك اللغة والثيم والتباين والكثافة وحجم ووزن وتباعد الخط وتقليل الحركة والتفضيلات البصرية؛ و`PlayerProvider` يملك إعدادات الاستماع. | متحقق محليًا. |
| وضع فاتح/داكن وسمات ديناميكية | ثيمات محفوظة، اختيار يدوي أو اتباع مظهر النظام، وحالة تباين عالٍ فوق الثيم الأساسي. | متحقق محليًا. |
| حفظ التفضيلات | تستعاد قيم الواجهة المتحققة من `AsyncStorage` وتطبق بعد الجاهزية؛ القيم غير الصالحة تعود إلى افتراضات آمنة. | متحقق؛ لا تعد تفضيلات الواجهة أسرارًا. |
| لغات وRTL/LTR | العربية والإنجليزية والفرنسية والإسبانية مع اتجاه مشتق من `LOCALE_META` وتحديث نص الواجهة لحظيًا. | متحقق؛ يلزم اختبار نصوص طويلة على جهاز فعلي. |
| تخزين حساس آمن | لا تحفظ المكتبة URI أو البيانات الحساسة في السجل؛ عند ظهور رمز أو اعتماد مستقبلي يستخدم التخزين الآمن بدل `AsyncStorage`. | حد معماري موثق؛ لا توجد أسرار تطبيقية محلية مطلوبة الآن. |

## 2. التنقل وتجربة الاستخدام

تستخدم Expo Router توجيهًا قائمًا على الملفات ومسارات مكتوبة، وليس «Named Routes» بالاصطلاح الخاص بـFlutter. أضيفت طبقة `APP_ROUTES` و`APP_ROUTE_DEFINITIONS` و`toSafeAppRoute` لتوحيد الوجهات البرمجية الحساسة ومنع تمرير وجهة غير معروفة إلى الواجهة. وتُقيّم `canAccessRoute` سياسة المسار صراحةً؛ وتبقى مسارات الوسائط المحلية متاحة من دون حساب أو مصادقة، بينما توجد السياسات المقيدة كعقد مستقبلي قابل للاختبار لا كميزة حسابات مضافة. كما يوفّر `app/+not-found.tsx` نقطة استرداد واضحة للمسارات غير المطابقة مع عودة ظاهرة إلى الرئيسية. توصي Expo Router بتخصيص المسار غير المطابق وربطه بواجهة تعيد المستخدم إلى البداية. [3]

| التحسين | النتيجة للمستخدم |
|---|---|
| `AppRecoveryScreen` | رسالة مفهومة وزر إعادة محاولة عند خطأ العرض، وزر عودة رئيسية دائمًا. |
| `+not-found` | الرابط القديم أو غير الصحيح لا يترك المستخدم في مسار غامض. |
| مسارات مركزية مكتوبة | نقاط الاسترداد لا تكرر سلاسل وجهات متناثرة. |
| انتقالات موجودة تحترم تقليل الحركة | انتقالات المظهر والتحميل لا تفترض أن الحركة مطلوبة لفهم الحالة. |

لا تُفرض «قاعدة ثلاث نقرات» بصورة مصطنعة؛ بل تُراجع التدفقات ذات القيمة العالية لتبقى قابلة للوصول من التبويبات أو الوصول السريع أو المشغّل المصغر مع بدائل مرئية للإيماءات.

## 3. الاستقرار ومنع الانهيارات

أضيف `ErrorBoundary` على مستوى جذر Expo Router ليعرض واجهة استرداد مستقلة عن مزودات الثيم والمشغل؛ وهذا مهم لأن أيًا من المزودات قد يكون سبب فشل العرض. يدعم Expo Router حدود الأخطاء المصدرة من المسار مع `retry`، ويرفع الخطأ إلى الحد الأقرب عند غيابه. [3]

| المجال | الضابط الحالي | حدود التحقق |
|---|---|---|
| أخطاء العرض | `ErrorBoundary` جذري وواجهة استرداد لا تعتمد على السياقات القابلة للفشل. | يغطي أخطاء العرض؛ لا يحوّل الأعطال الأصلية القاتلة إلى أخطاء قابلة للاسترداد. |
| تهيئة بيئة المعاينة | حماية `initManusRuntime` واشتراك المساحات الآمنة بـ`try/catch` مع بقاء القيم الافتراضية. | لا تخفي خطأ منطق الأعمال؛ تمنع تكامل المعاينة الاختياري من حجب الواجهة. |
| حدود الاتصال | `withTimeout` مركزي بمهلة شبكة افتراضية قدرها 12 ثانية، مع `AbortController` وأخطاء منفصلة لانتهاء المهلة أو إلغاء العملية. | يطبقه عميل REST وناقل tRPC؛ لا يثبت صحة خدمة بعيدة أو إتاحة الشبكة على الجهاز. |
| الاستيراد والتشغيل | تحقق URI واسم الملف والحجم، دفعات محدودة، معالجة إلغاء وفشل، وتنظيف الملف المُدار عند الفشل. | تخضع للملفات والأذونات الفعلية على الجهاز. |
| الذاكرة والمستمعات | تنظيف اشتراك المظهر ومؤقت النوم واشتراك المساحة الآمنة؛ عمر لاعب الصوت ضمن hook أصلي. | يتطلب قياسًا أصليًا طويلًا لاكتشاف تسربات المنصة. |
| التخزين المستعاد | تحليل محمي، مرشحات للأنواع، وحدود لطول القوائم والنصوص. | تُغطيها اختبارات وحدات وعقود؛ يظل اختبار ترحيل نسخة قديمة مطلوبًا. |

## 4. جودة الشفرة والأمن

يفصل المشروع الحالة عن الواجهة، ويعيد استخدام طبقات التحقق والسمات والمشغل والمكونات البصرية. أضيفت طبقة تنقل صغيرة قابلة للاختبار بدل تكرار منطق الوجهات في حالات الاسترداد. لا يُسمح بتسجيل مسارات ملفات المستخدم أو URI أو رموز الجلسة؛ كما تبقى بيانات الوسائط محلية افتراضيًا.

| الطلب | القرار المتوافق مع Expo |
|---|---|
| SOLID ومنع التكرار | استمر في فصل الحالة (`lib/omniwave`) والواجهة (`app/`, `components/`) والتحقق (`validation.ts`)؛ أضف مكونًا مشتركًا عند تكرار سلوك، لا عند تشابه شكلي فقط. |
| تشفير البيانات الحساسة | لا تخزن أسرارًا أو بيانات اعتماد في المكتبة المحلية؛ استخدم SecureStore لأي رمز مستقبلي، ولا تضع الأسرار في `AsyncStorage` أو المستودع. |
| حقن الشفرة | تعامل مع URI وأسماء الملفات والبيانات الوصفية كمدخلات غير موثوقة، ولا تمررها إلى أوامر shell أو HTML أو سجلات الإنتاج. |
| HTTPS وSSL Pinning | الاتصالات الخادمة تستخدم HTTPS؛ لا يُضاف SSL pinning شكليًا في JavaScript. يتطلب pinning قرارًا أصليًا ومراجعة تدوير الشهادات ودعم الحوادث قبل إدخاله. |
| التمويه | استخدم إعدادات بناء الإنتاج القياسية في Expo/Hermes ولا تعتمد على التمويه بديلاً عن التحقق، عدم تضمين أسرار، وأقل أذونات. |

## 5. الاختبارات والجاهزية للمتاجر

تشمل الاختبارات الحالية بيانات الموسيقى والفيديو، الخصوصية، الاستقرار، المشاركة والتصدير، VTT، الترجمة، الواجهة، والصقل البصري. وتغطي الاختبارات الجديدة اكتمال العملية قبل المهلة، وانتهاء المهلة وإلغاء المتصل، وسياسات المسارات، وعقد الربط بين حد المهلات وعميلَي REST وtRPC، وعدم عودة `any` الصريح إلى ملفات النواة المقواة. كما تؤكد اختبارات الواجهة وجود مسار غير مطابق وحاجز أخطاء واسترداد متاح. أضافت جولة العناية الواجبة عقدًا لأقل الأذونات وإخفاء سجلات وسيط التخزين وفحص الاعتمادات في CI. أضاف التدقيق الجنائي حارس عنوان API وإعادة محاولة محدودة وسجل تشخيص منقح. في جولة التحقق النهائية نجحت **81 حالة Vitest**، مع حالة واحدة متخطاة ومعلّمة صراحةً؛ كما نجح فحص الفروقات وTypeScript وESLint والتحقق من إعداد Expo.

| بوابة | الحالة قبل حفظ إصدار | الدليل |
|---|---|---|
| TypeScript | مطلوب | `pnpm check` |
| ESLint | مطلوب | `pnpm lint` |
| Vitest | مطلوب | `pnpm test` |
| سلامة الفروقات | مطلوب | `git diff --check` |
| إعداد Expo | مطلوب عند تعديل البناء | `pnpm exec expo config --type public` |
| التكامل المستمر | مفعل على `main` وطلبات الدمج | `.github/workflows/quality.yml` يشغّل النوع والـlint وإعداد Expo والاختبارات |
| iOS وAndroid فعليان | إلزامي لتدفقات أصلية | [مصفوفة الاختبار الأصلية](NATIVE_TEST_MATRIX_IOS_ANDROID.md) |

يحتوي `app.config.ts` على هوية الحزمة وأصول الأيقونة ووضع الخلفية للصوت ووسائط الفيديو والأذونات الأقل المطلوبة وإضافات البناء. لا تتضمن ملفات المستودع شهادات توقيع المتجر أو سجلات حسابات Apple/Google؛ تُدار هذه القيم خارج الشفرة. لا يُنشر التطبيق من بيئة التطوير: بعد اعتماد الاختبارات وحفظ نقطة استعادة، استخدم زر **Publish** في واجهة المشروع لإنشاء عملية البناء وAPK.

## قائمة اعتماد الإصدار

- [ ] اختيار رقم الإصدار وبناء الإنتاج ومراجعته في Expo config.
- [ ] تنفيذ بوابات الجودة الآلية وتوثيق نتائجها.
- [ ] مراجعة الأذونات الفعلية وبيان الخصوصية المحلي ومحتوى التصدير والمشاركة.
- [ ] تنفيذ صفوف iOS وAndroid ذات الصلة في مصفوفة الاختبار بمحتوى مرخص أو مملوك.
- [ ] اختبار العربية وLTR وحجم النص والتباين وتقليل الحركة وقارئ الشاشة.
- [ ] مراجعة حزمة المتجر واللقطات والوصف وبيانات الاتصال وسياسة الخصوصية في بوابات المتاجر.
- [ ] حفظ نقطة استعادة قبل اختيار Publish.

## ما لم يُدَّعَ أنه مكتمل

لا تقدم هذه الوثيقة ادعاءً بأن بناء المتجر النهائي أو توقيعه أو Obfuscation خاصًا أو SSL pinning أو تشغيل الخلفية أو Bluetooth أو PiP قد اختبر بالكامل في هذه البيئة. هذه عناصر تحتاج بناءً أصليًا وقياسًا واختبارًا يدويًا موثقًا، وليست خصائص يمكن ضمانها من معاينة الويب.
