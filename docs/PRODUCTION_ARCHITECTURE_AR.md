# معمارية OmniWave الإنتاجية

## قرار معماري

OmniWave تطبيق وسائط **محلي أولًا** مبني بـExpo وReact Native. لذلك تعتمد المعمارية الإنتاجية مزودات React محلية وعقود TypeScript وإجراءات حالة مسماة، بدل إدخال Redux أو Bloc لمجرد استبدال أدوات قائمة. تكون إعادة الهيكلة تدريجية: تفصل الحدود الجديدة وتبقي التشغيل المحلي والإتاحة والخصوصية مستقرة في كل إصدار.

> لا تفرض المصادقة على مكتبة الموسيقى أو الفيديو أو الإعدادات المحلية. حراس الخادم موجودون فقط للإجراءات الخادمة المحمية، بينما تبقى مسارات الوسائط المحلية قابلة للاستخدام بلا حساب أو اتصال.

## الطبقات المستهدفة

| الطبقة | المسؤولية | أمثلة ضمن OmniWave | قاعدة الاعتمادية |
|---|---|---|---|
| العرض | الشاشات والمكونات والإتاحة والرسوم والحالات المرئية | `app/` و`components/` | تستدعي إجراءات حالة أو حالات عرض فقط. |
| التطبيق | تنسيق حالات الاستخدام وإدارة مسار الخطأ | مزودات المشغل والثيم والفيديو، وحراس المسارات | لا تعرف تفاصيل العنصر المرئي. |
| المجال | نماذج وقواعد نقية وتحقق وقرارات قابلة للاختبار | `types.ts` و`validation.ts` و`media-stability.ts` | لا تستورد Expo أو React. |
| البنية التحتية | التخزين المحلي والملفات ومنتقي النظام والصوت والشبكة | AsyncStorage وFileSystem وDocumentPicker و`api.ts` | تمرر أخطاء مصنفة ولا تكشف مسارات المستخدم. |

## مصدر الحقيقة الوحيد للإعدادات

`ThemeProvider` هو مصدر الحقيقة لتفضيلات الواجهة المحلية: الثيم واللون واتجاه اللغة والكثافة وحجم ووزن وتباعد النص والحركة والإتاحة. تستعاد البيانات بعد تحقق بنيوي، وتطبق متغيرات التصميم في وقت التشغيل، وتراقب مظهر النظام مع تنظيف الاشتراك عند فك التركيب. تبقى إعدادات المشغل في `PlayerProvider` لأن لها دورة حياة تشغيل مستقلة.

| المتطلب | التنفيذ |
|---|---|
| ثيمات فاتحة وداكنة ومخصصة | `APP_THEMES` مع رموز تصميم مشتقة وطبقة تباين عالٍ. |
| تطبيق لحظي بلا إعادة تشغيل | تحديث حالة تفاعلية وربط NativeWind و`Appearance` في Effect واحد. |
| RTL/LTR وتحويل اللغة | `LOCALE_META` تحدد الاتجاه، و`translate()` توفر استرجاعًا إلى الإنجليزية ثم العربية عند نقص مفتاح وقت التشغيل. |
| تخزين حساس | لا توجد أسرار لازمة للتشغيل المحلي؛ أي رمز حساب مستقبلي يستخدم تخزينًا آمنًا ولا يدخل AsyncStorage أو السجل. |

## التنقل والحراسة

يستخدم التطبيق Expo Router ومسارات ملفات مكتوبة. تكون طبقة `APP_ROUTES` هي قائمة الوجهات التي تستخدمها حالات الاسترداد والتنقل البرمجي، وتعيد `toSafeAppRoute()` أي قيمة غير موثوقة إلى الرئيسية. يعرض `+not-found` واجهة تعافٍ للمسارات غير المطابقة، بينما يعرض `ErrorBoundary` في التخطيط الجذري زر إعادة المحاولة عند خطأ عرض.

| سياسة المسار | السلوك |
|---|---|
| مكتبة أو تشغيل أو قوائم أو إعدادات محلية | مسموح بلا مصادقة، لأن التطبيق يعمل دون حساب. |
| إجراء خادمي محمي مستقبلًا | ينفذ الخادم `protectedProcedure` أو `adminProcedure`؛ لا تعتمد الحماية على إخفاء شاشة العميل. |
| وجهة غير معرفة أو بيانات مسار غير موثوقة | استعادة إلى الرئيسية مع واجهة قابلة للوصول. |

## الموثوقية والشبكة

تحتوي طبقات الوسائط على تحقق للـURI والاسم والحجم وحدود للدفعات، واستعادة محلية محمية، وتنظيف للملفات المدارة عند الفشل. يجب أن تمر اتصالات HTTP عبر عميل مركزي بمهلة وإلغاء وتصنيف عام للخطأ، بدل تكرار `fetch()` في الشاشات. لا ينفذ SSL pinning شكليًا في TypeScript؛ إن احتاج المنتج إليه مستقبلًا فيجب أن يمر بقرار بناء أصلي وتدوير شهادات وخطة استرداد.

## قواعد الإنتاج

لا تعد المعاينة دليلًا على الخلفية أو شاشة القفل أو Bluetooth أو PiP أو أذونات النظام أو التدوير. قبل النشر، شغّل فحص الأنواع والـLint والاختبارات وفحص الفروقات وإعداد Expo، ثم نفذ صفوف iOS وAndroid الملائمة في [مصفوفة الاختبار الأصلية](NATIVE_TEST_MATRIX_IOS_ANDROID.md). احفظ نقطة استعادة قبل إنشاء البناء من زر Publish، ولا تبنِ APK يدويًا في بيئة التطوير.
